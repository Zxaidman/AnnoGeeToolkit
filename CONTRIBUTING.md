# Contributing to AnonGee Toolkit

AnonGee Toolkit is proprietary software. Contributions are not accepted under
an open-source contribution model.

## Approved collaborators only

Source-code access and contribution rights are limited to collaborators who
have been explicitly approved by Zxaidman.

Repository access, issue participation, code review, or discussion does not by
itself grant permission to copy, publish, redistribute, sublicense, sell, or
independently exploit AnonGee Toolkit source code.

## Before contributing code

Do not submit a substantial human-authored code contribution unless contribution
terms have been agreed with Zxaidman in advance.

Those terms must give Zxaidman sufficient rights to maintain, modify,
commercialize, distribute, sublicense, and relicense AnonGee Toolkit, including
future proprietary and commercial editions. Depending on the collaboration,
this may be handled through copyright assignment, an exclusive license, or
another written contributor/IP agreement.

A pull request, commit, GitHub account permission, or verbal discussion is not
a substitute for any required contributor/IP agreement.

## AI-assisted development

AI tools may be used as development assistants subject to the applicable tool
terms and project review requirements. AI-generated or AI-assisted output must
be reviewed by the responsible human developer for correctness, security,
licensing concerns, provenance concerns, and compatibility before it is merged.

Do not knowingly introduce third-party copyrighted code, training examples,
licensed snippets, or other material that AnonGee Toolkit does not have the
right to use.

## Third-party dependencies

New dependencies require review before they are added. At minimum, a proposed
dependency should identify:

- package/project name and exact version;
- upstream source;
- applicable license;
- whether native binaries are bundled;
- whether commercial redistribution is permitted;
- whether attribution, NOTICE, source-offer, or other obligations apply; and
- whether the dependency conflicts with AnonGee Toolkit's proprietary
  distribution model.

Runtime dependencies must remain pinned through the project's controlled build
process unless a deliberate update is approved and tested.

## Branch and review policy

Use a dedicated feature or maintenance branch. Keep unrelated changes out of a
single pull request. Changes affecting runtime dependencies, installer
behavior, licensing, deployment, or compatibility contracts require explicit
review before merge.

The project follows semantic versioning for released software and build
milestones where applicable.

## No implied license

Submitting an issue, suggestion, idea, test result, or other feedback does not
grant access to the proprietary source code and does not change the licensing
terms of AnonGee Toolkit.

For licensing, commercial distribution, reseller, source-access, or contributor
arrangements, contact Zxaidman directly or an expressly authorized
representative.
